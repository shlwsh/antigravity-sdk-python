# 05 生命周期拦截 (Hooks) 与声明式策略 (Policies)

为了保障大语言模型调用工具时的安全性，并提供强大的可观测性，Google Antigravity SDK 设计了严密的**生命周期拦截 (Hooks) 机制**与一套开箱即用的**声明式策略 (Policies) 引擎**。

---

## 🪝 Hook 分类学 (Taxonomy)

为了保证执行顺序可预测并降低副作用，SDK 将 Hooks 划分为三类：

```
                    ┌──────────────────────────────┐
                    │          事件发生            │
                    └──────────────┬───────────────┘
                                   │
                                   ▼
        1. Decide Hooks (决定) ────► 拦截/审查？(是 -> 终止)
                                   │ (否/放行)
                                   ▼
                            [ 执行实际操作 ]
                                   │
                                   ▼
        2. Transform Hooks (转换) ─► 是否出错？(是 -> 转换错误/容错)
                                   │
                                   ▼
        3. Inspect Hooks (审计) ───► 审计/日志 (不影响控制流)
```

1. **Decide Hooks (只读，阻塞控制流)**
   - **目的**：安全准入与合规审查。
   - **行为**：接收事件数据，返回 `HookResult` 指明是否允许执行（`allow=True` 或 `allow=False`）。**不能修改数据**，如果拒绝，执行流立即中断。
   - **示例**：`PreToolCallDecideHook`
2. **Transform Hooks (可修改，阻塞控制流)**
   - **目的**：数据脱敏、Prompt 过滤、错误恢复与人机交互。
   - **行为**：接收数据，允许对数据进行修改，并必须返回修改后的数据。如果执行失败，触发 fail-closed 拒绝操作。
   - **示例**：`OnToolErrorHook` (工具出错拦截器)、`OnInteractionHook` (澄清提问交互器)
3. **Inspect Hooks (只读，非阻塞控制流)**
   - **目的**：可观测性、日志审计、指标统计。
   - **行为**：接收数据，但**无法修改数据，且不能阻止或延误主流程的执行**。通常在操作异步完成后并发调度。
   - **示例**：`PostToolCallHook`、`OnCompactionHook`

## 🔒 顺序防御与 TOCTOU 漏洞保护

为防止**检查时间与使用时间不一致 (Time-of-Check to Time-of-Use, TOCTOU)** 导致的安全漏洞，SDK 强制推行严格的阶段执行顺序：

$$\text{Decide Hook 拦截审查} \rightarrow \text{执行核心操作 (如工具调用)} \rightarrow \text{Inspect Hook 审计记录}$$

- **Fail-Closed 默认闭合安全姿态**：在决定阶段，一旦有任何一个 Decide Hook 明确表示拒绝（`allow=False`），该操作会被**立刻终止**，后续的 Decide Hooks 也不会再被调度。
- **错误恢复隔离**：如果在执行操作期间工具抛出异常，将会唤醒 Transform 类型的 `OnToolErrorHook`，从而拦截抛出的原始堆栈，将其包装为 LLM 可读的安全提示或自动修复指令。

## 🌲 层次化上下文系统

Hooks 运行在一个具有继承关系的上下文容器中：

1. **`SessionContext` (会话上下文)**：作用域贯穿整个 Agent 交互生命周期。
2. **`TurnContext` (回合上下文)**：单次 Prompt-Response 对话范围。**继承自 `SessionContext`**。
3. **`OperationContext` (操作上下文)**：单个具体操作（如一次特定的工具调用）。**继承自 `TurnContext`**。

利用该继承树，高层作用域的数据可以无缝向下传递，实现状态追踪与调用链标识：

```python
# 示例：通过上下文传递 Turn 关联 ID 标识
@hooks.pre_turn
async def trace_turn(context: HookContext, prompt: types.Content):
    # 在回合开始时，将 correlation_id 写入 TurnContext
    context.set("correlation_id", "req-123456")

@hooks.post_tool_call
async def audit_tool(context: HookContext, result: types.ToolResult):
    # 在工具执行后，可以读取到 correlation_id，实现日志关联
    corr_id = context.get("correlation_id")
    print(f"[{corr_id}] 工具 {result.name} 已执行。")
```

## 📝 声明式策略 (Policies) 引擎

为了避免手写底层的 `PreToolCallDecideHook`，SDK 提供了一套声明式安全策略配置（`policy` 模块）。你只需定义规则列表，SDK 就会自动编译成高效的安全拦截逻辑。

### 优先评估模型 (Priority Model)

策略评估规则遵循**特异度 (Specificity) 与安全性**分层，并在层级内部实行**首位匹配即短路 (First Match Wins)** 的原则：

| 优先级 (Level) | 规则匹配特异度 | 决策行为 (Decision) | 示例 |
| :--- | :--- | :--- | :--- |
| **1** | 特定工具名 (Specific) | **DENY** (拒绝) | `policy.deny("run_command")` |
| **2** | 特定工具名 (Specific) | **ASK_USER** (人工审批)| `policy.ask_user("run_command", handler=...)` |
| **3** | 特定工具名 (Specific) | **APPROVE** (放行) | `policy.allow("run_command")` |
| **4** | 通配符 `*` (Wildcard) | **DENY** (全部拒绝) | `policy.deny_all()` / `policy.deny("*")` |
| **5** | 通配符 `*` (Wildcard) | **ASK_USER** (全部审批)| `policy.ask_user("*", handler=...)` |
| **6** | 通配符 `*` (Wildcard) | **APPROVE** (全部放行) | `policy.allow_all()` / `policy.allow("*")` |

## 💻 策略与自定义 Hook 完整示例

### 代码实现

新建文件 `hooks_policies_demo.py`：

```python
import asyncio
from google.antigravity import Agent, LocalAgentConfig, types
from google.antigravity.hooks import hooks, policy

# 1. 使用装饰器定义自定义的 Inspect Hook (生命周期观察)
@hooks.post_turn
async def on_turn_completed(response_text: str):
    print(f"\n[审计日志] 回合结束。模型回复长度: {len(response_text)} 字符。\n")

# 2. 定义审批 Handler (当触发 ASK_USER 策略时执行)
async def my_user_approval(tool_call: types.ToolCall) -> bool:
    print(f"\n📢 [审批拦截] 工具调用申请: {tool_call.name}")
    print(f"📢 [参数内容]: {tool_call.args}")
    user_input = input("确认执行此操作吗？(y/n): ")
    return user_input.strip().lower() == 'y'

async def main() -> None:
    # 3. 组装声明式安全策略
    policies = [
        # 3.1 默认阻断所有工具（安全基线姿态：Deny by Default）
        policy.deny_all(),
        # 3.2 允许免审批读取文件目录
        policy.allow(types.BuiltinTools.LIST_DIR.value),
        # 3.3 允许使用命令行工具，但在执行删除(rm)时强行拒绝，其余安全命令人工审批
        policy.deny(
            types.BuiltinTools.RUN_COMMAND.value,
            when=lambda args: "rm" in args.get("CommandLine", ""),
            name="block-rm-commands"
        ),
        policy.ask_user(
            types.BuiltinTools.RUN_COMMAND.value,
            handler=my_user_approval,
            name="verify-commands"
        )
    ]

    config = LocalAgentConfig(
        policies=policies,
        # 注册自定义观察 Hook
        hooks=[on_turn_completed]
    )

    async with Agent(config) as my_agent:
        # 这个动作属于 LIST_DIR，应该被直接放行
        print("--- 执行免审批工具测试 ---")
        res1 = await my_agent.chat("列出当前目录下的文件")
        print(f"Agent: {await res1.text()}")

        # 这个动作包含 rm 敏感词，应该被策略直接强行拒绝，LLM 获得 Refusal 信息
        print("\n--- 执行敏感阻断测试 ---")
        res2 = await my_agent.chat("请用命令行删除敏感日志文件: rm -f /tmp/sys.log")
        print(f"Agent: {await res2.text()}")

        # 这个动作没有 rm 敏感词，会挂起并唤醒 my_user_approval 回调，由用户终端决定
        print("\n--- 执行命令行人工审批测试 ---")
        res3 = await my_agent.chat("请用命令行输出系统的当前日期")
        print(f"Agent: {await res3.text()}")

if __name__ == "__main__":
    asyncio.run(main())
```
