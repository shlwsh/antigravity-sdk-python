# 09 项目运行与功能全景

本章说明**本仓库是什么、如何在本机跑起来**，以及 SDK **开箱/可配置实现哪些能力**。适合第一次打开 `antigravity-sdk-python` 仓库的开发者。

---

## 项目定位

| 项目 | 说明 |
| :--- | :--- |
| **类型** | Python SDK 库（`google-antigravity`），不是独立桌面/服务端产品 |
| **用途** | 用 Gemini + Local Harness（Go 运行时）构建可调用工具、可审计、可持久化的 AI Agent |
| **本仓库** | SDK 源码 + 可运行示例；**不包含**可直接运行的 Harness 二进制（二进制在 PyPI 平台 wheel 内） |
| **Python 版本** | `>=3.10`（见 `pyproject.toml`） |

---

## 运行前提

### 1. 安装 SDK（含 Harness 二进制）

在 **Debian / Ubuntu / WSL** 等系统上，系统 Python 受 [PEP 668](https://peps.python.org/pep-0668/) 保护，直接 `pip install` 会报错 `externally-managed-environment`。**请使用虚拟环境**（不要用 `--break-system-packages` 装到系统 Python）：

```bash
cd /path/to/antigravity-sdk-python

# 创建并启用虚拟环境（仅需一次）
python3 -m venv .venv
source .venv/bin/activate   # Windows CMD: .venv\Scripts\activate.bat
                            # PowerShell:   .venv\Scripts\Activate.ps1

pip install --upgrade pip
pip install google-antigravity
```

之后每次新开终端（推荐同时加载 `.env`，见下一节）：

```bash
cd /path/to/antigravity-sdk-python
source .venv/bin/activate
set -a && source .env && set +a   # 若已配置 .env
python examples/getting_started/hello_world.py
```

未使用 venv 时也可用 `pipx install google-antigravity` 单独装 CLI 式环境，但跑本仓库示例仍推荐项目内 `.venv`。

> **仅 `git clone` 本仓库无法单独运行 Agent。** 必须从 [PyPI](https://pypi.org/project/google-antigravity/) 安装（或安装已打入 `google/antigravity/bin/localharness` 的 wheel），否则启动时会找不到 Local Harness 可执行文件。

可选：在仓库内开发时，仍建议先 `pip install google-antigravity` 保证二进制存在；若你从源码打 wheel，需按发布流程将对应平台的 `localharness` 放入 `google/antigravity/bin/` 再 `pip install` 该 wheel。

### 2. 配置 Gemini 访问（API Key 与 `.env`）

本仓库根目录提供：

| 文件 | 说明 |
| :--- | :--- |
| `.env.example` | 模板，可提交到 Git |
| `.env` | 本地真实密钥，**已在 `.gitignore` 中忽略** |

**首次配置：**

```bash
cd /path/to/antigravity-sdk-python
cp .env.example .env
# 编辑 .env，填入在 AI Studio 申请的 Key：
#   GEMINI_API_KEY=your_api_key_here
```

**加载方式（SDK 不会自动读 `.env`，需由 shell 导出环境变量）：**

```bash
source .venv/bin/activate
set -a && source .env && set +a
# 验证是否生效（应显示 Key 前缀，勿在公共场合执行）：
# echo "${GEMINI_API_KEY:0:8}..."
```

其它配置方式：

```bash
# 方式 B：当前 shell 临时导出（不落盘）
export GEMINI_API_KEY="your_api_key_here"
```

```python
# 方式 C：代码内简写（不推荐提交到 Git）
LocalAgentConfig(api_key="your_api_key_here")
```

```python
# 方式 D：Vertex AI（企业 GCP）
LocalAgentConfig(
    vertex=True,
    project="your-gcp-project",
    location="us-central1",
)
```

密钥解析顺序（启动 `Agent` 时）：`GeminiConfig.api_key` / `ModelEntry.api_key` → 环境变量 `GEMINI_API_KEY`。详见 [08_权限机制与LLM调用](./08_权限机制与LLM调用.md)。

> [!WARNING]
> **安全**：勿将 API Key 写入会被 Git 跟踪的文件、聊天记录或截图。若密钥已泄露，请到 [Google AI Studio](https://aistudio.google.com/app/api-keys) 撤销并重新创建，再更新 `.env`。

### 3. Google 账号与「共享使用」说明

本 SDK **不支持**用 Google 账号做 OAuth 浏览器登录；与 Google 账号的关系是：**在网页上申请凭证，再把凭证交给 SDK**。

| 场景 | 做法 |
| :--- | :--- |
| **个人开发** | 用 Google 账号登录 [Google AI Studio](https://aistudio.google.com/app/api-keys) → 创建 API Key → 写入 `.env` 的 `GEMINI_API_KEY` |
| **小团队共用** | 在 AI Studio 创建团队/项目 Key，放入 1Password、Vault、K8s Secret 等；每人本机 `source .env` 或 CI 注入环境变量。**不要**在仓库或聊天中明文共享 |
| **每人独立** | 各用各的 Google 账号申请 Key，各自维护 `.env`（配额隔离，最安全） |
| **企业 / GCP** | `vertex=True` + `project` + `location`；本机可先 `gcloud auth application-default login`，团队用**服务账号** + IAM，而非共用个人 Gmail 密码 |

SDK **明确不提供**：OAuth 登录流、多用户会话切换、Workspace 账号密码登录。认证在 Local Harness（Go）内完成，Python 仅传递 `api_key` / Vertex 相关字段。

### 4. 本仓库验证 `hello_world.py`

在已完成 venv 安装、`.env` 已填写 `GEMINI_API_KEY` 的前提下：

```bash
cd /path/to/antigravity-sdk-python
source .venv/bin/activate
set -a && source .env && set +a
python examples/getting_started/hello_world.py
```

**预期输出（节选）：**

```
  User: Say 'Hello World!'
  Agent: Hello World!
```

验收标准（见示例文件头注释）：进程退出码 `0`、Agent 返回非空文本且包含问候语。若失败，先看下文「常见问题」。

也可直接运行仓库内示例，无需自建 `hello_world.py`：

```bash
python examples/getting_started/hello_world.py
```

## 如何运行（推荐路径）

### 路径 A：venv + `.env` + 仓库内示例（推荐）

```bash
cd /path/to/antigravity-sdk-python

python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip google-antigravity

cp .env.example .env
# 编辑 .env 填入 GEMINI_API_KEY
set -a && source .env && set +a

python examples/getting_started/hello_world.py
python examples/getting_started/streaming.py
# python examples/deep_dives/interactive_cli.py
```

每个示例文件头部通常有 `To run:` 与验收说明（`Criteria for correct script performance`）。

### 路径 B：最小自写脚本

在任意目录新建 `quickstart.py`：

```python
import asyncio
from google.antigravity import Agent, LocalAgentConfig

async def main() -> None:
    async with Agent(LocalAgentConfig()) as agent:
        response = await agent.chat("用一句话介绍 Google Antigravity SDK。")
        print(await response.text())

if __name__ == "__main__":
    asyncio.run(main())
```

```bash
source .venv/bin/activate
set -a && source .env && set +a
python quickstart.py
```

### 路径 C：交互式多轮对话 CLI

```python
import asyncio
from google.antigravity import Agent, LocalAgentConfig
from google.antigravity.types import CapabilitiesConfig
from google.antigravity.hooks import policy
from google.antigravity.utils.interactive import run_interactive_loop

async def main() -> None:
    config = LocalAgentConfig(
        capabilities=CapabilitiesConfig(),  # 启用全部内置工具
        policies=[policy.allow_all()],      # 含 shell；仅可信环境
    )
    async with Agent(config) as agent:
        await run_interactive_loop(agent)

asyncio.run(main())
```

`run_interactive_loop` 会把默认对 `run_command` 的 **DENY** 升级为终端 **y/n 确认**（见 `utils/interactive.py`）。

### 路径 D：运行单元测试（贡献者）

```bash
pip install google-antigravity "pytest>=7.0"
# 在仓库根目录
pytest google/antigravity/ -q
```

部分测试 mock 了 Harness；集成行为仍依赖已安装的 `localharness` 二进制。

## 启动时实际发生了什么

一次 `async with Agent(LocalAgentConfig()) as agent` 会：

1. 创建 `HookRunner`，注册 `hooks` 与 `policy.enforce(policies)`；
2. 连接 `mcp_servers`（若有），合并 MCP 工具到 `ToolRunner`；
3. `LocalConnectionStrategy` 启动 **Go localharness 子进程**，经 WebSocket 发送 `InitializeConversationEvent`（模型名、API Key、工具列表、工作区等）；
4. 创建 `Conversation`，后续 `chat()` 通过 Harness 调用 Gemini 并驱动 Agentic 循环。

详见 [02_核心架构](./02_核心架构.md)、[08_权限机制与LLM调用](./08_权限机制与LLM调用.md)。

## 默认能力与「安全基线」

`LocalAgentConfig()` 未改参数时的典型行为：

| 项 | 默认值 |
| :--- | :--- |
| 主模型 | `gemini-3.5-flash` |
| 内置工具 | `CapabilitiesConfig()` → Harness **启用全部**内置工具 |
| 策略 | `confirm_run_command()` → **拒绝** `run_command`，其它工具放行 |
| 工作区 | `workspaces=[os.getcwd()]` → 自动 prepend `workspace_only`，文件类工具限当前目录 + `app_data_dir` |
| MCP / 自定义工具 | 无，需自行配置 |

> README 中「只读模式」常指**未显式放开 shell / 写能力时的安全用法**。若要做到**模型上下文里只有只读工具**，请显式：
>
> `capabilities=CapabilitiesConfig(enabled_tools=BuiltinTools.read_only())`

启用**写工具或 MCP** 且**无任何** `policies` / `PreToolCallDecideHook` 时，`Agent` 启动会 **ValueError**（强制声明安全策略）。

## 常见问题

### `error: externally-managed-environment`

系统 Python 不允许全局 `pip install`。在项目目录执行 `python3 -m venv .venv && source .venv/bin/activate`，再在 venv 内 `pip install google-antigravity`。

### `Failed to read length from stdout` / 找不到 binary

未安装 PyPI wheel 或平台 wheel 不含当前 OS/架构的 `localharness`。请 `pip install google-antigravity` 并确认安装包内存在 `google/antigravity/bin/`。

### `A Gemini API key is required`

说明环境变量未注入。请 `set -a && source .env && set +a` 后再运行，或 `export GEMINI_API_KEY=...`。注意：**SDK 不会自动加载 `.env` 文件**。

### 已配置 `.env` 仍报缺 Key

确认是在**同一终端**先 `source .env` 再 `python`；新开终端需重新执行 `set -a && source .env && set +a`。

### `Write tools or MCP servers are enabled without a safety policy`

为 `LocalAgentConfig` 增加 `policies=[policy.allow_all()]`（或更细的 deny/ask 规则）。参见 [08_权限机制与LLM调用](./08_权限机制与LLM调用.md)。

### 从源码 `pip install -e .` 仍无法运行

可编辑安装只链接 Python 代码；**仍需** release 流程提供的 Harness 二进制。开发时通常 **PyPI 安装 + 本地改代码调试** 或打完整 wheel。
