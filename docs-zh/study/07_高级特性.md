# 07 高级特性 (Advanced Features)

本章将介绍 Google Antigravity SDK 中的几项高级生产力特性：多模态内容摄入、会话状态持久化、子 Agent 委派以及交互式控制台运行循环。

---

## 📷 多模态数据摄入 (Multimodal Ingestion)

Gemini 模型原生支持对图像、文档（如 PDF）、音频和视频进行混合输入。SDK 提供了四种基类为 `_BaseMedia` 的多模态实体类以及一个自动识别工具：

- **`Image`**：图像数据输入。
- **`Document`**：文档数据输入（例如 PDF）。
- **`Audio`**：音频数据输入.
- **`Video`**：视频数据输入。
- **`from_file(path, description=None)`**（推荐）：自动工具函数。它会读取给定路径的文件，猜测其 MIME 格式，并实例化为上述四种具体的类。

### 示例：混合多模态 Prompt 输入

```python
from google.antigravity import Agent, LocalAgentConfig
from google.antigravity.types import Image, from_file

async def main() -> None:
    config = LocalAgentConfig()
    async with Agent(config) as my_agent:
        # 1. 方式一：使用便捷工具从本地路径读取，自动猜测类型为 Document 实例
        pdf_spec = from_file("docs/architecture_spec.pdf", description="架构设计文档")

        # 2. 方式二：手动传入 raw 字节流和 MIME 类型构建 Image 实例
        chart_image = Image(
            data=b"raw_png_bytes...",
            mime_type="image/png",
            description="时序图结构"
        )

        # 3. 混合组装为 List
        prompt = [
            "请对比此图表中的拓扑结构是否符合架构设计文档中的要求，并列出3个潜在的安全风险：",
            chart_image,
            pdf_spec
        ]

        # 4. 直接传入 List 派发聊天
        response = await my_agent.chat(prompt)
        print(await response.text())
```

## 💾 会话状态持久化与恢复 (Session Persistence)

当需要在进程重启、微服务漂移或跨越用户会话后继续上一次的对话时，可以使用持久化机制。这主要由两个配置参数决定：

- **`save_dir`**：指定本地或共享目录。SDK 会将该会话的聊天历史（Trajectory）、临时产物（Artifacts）和多媒体资源持久化写入该位置。
- **`conversation_id`**：会话的唯一标识符。在第一轮对话建立后，可以通过 `agent.conversation_id` 获取。

### 示例：保存与重新加载会话

```python
from google.antigravity import Agent, LocalAgentConfig

# --- 步骤 1：开启会话并保存数据 ---
async def start_session() -> str:
    # 必须指定 `save_dir`，SDK 才会把数据落盘
    config = LocalAgentConfig(save_dir="/tmp/my_agent_save_dir")
    async with Agent(config) as agent:
        await agent.chat("记住：我的幸运数字是 42。")
        
        # 提取运行时分配的 ID
        conv_id = agent.conversation_id
        print(f"分配到的会话 ID: {conv_id}")
        return conv_id  # 例如: "c-12345-6789"

# --- 步骤 2：在后续的另一进程或时间恢复会话 ---
async def resume_session(conv_id: str) -> None:
    # 传入相同的 save_dir 和之前的 conversation_id
    config = LocalAgentConfig(
        save_dir="/tmp/my_agent_save_dir",
        conversation_id=conv_id
    )
    async with Agent(config) as agent:
        # Agent 将无缝拥有第一回合的记忆
        response = await agent.chat("我的幸运数字是什么？")
        print(f"Agent 回复: {await response.text()}")
```

## 🤖 子 Agent 机制 (Subagents)

当任务非常宏大（如：检索整个庞大项目并撰写教学大纲）时，如果将所有文档全部读入主 Agent 的上下文，会导致上下文窗口很快被塞满，且引入过多干扰噪声。

**子 Agent 机制**允许主 Agent 委派复杂的细节任务给一个独立的子协程。子 Agent 会自主探索、调用工具并整理数据，最后仅将**总结精简后的结果**发回给主 Agent。

### 启用方法
在 `CapabilitiesConfig` 中确保 `enable_subagents=True`（默认即为 `True`）：
```python
from google.antigravity.types import CapabilitiesConfig

config = LocalAgentConfig(
    capabilities=CapabilitiesConfig(enable_subagents=True)
)
```

### 🧬 Hook 在子 Agent 内部的传播与隔离规则
1. **统一拦截拦截规则**：启动子 Agent 在底层等同于发起一次 `types.BuiltinTools.START_SUBAGENT.value` 工具调用。
2. **Hook 穿透传播**：父 Agent 注册的工具安全拦截 Hooks（如 `PreToolCallDecideHook`）会**穿透传播到所有的子 Agent 中**。
3. **安全继承**：如果子 Agent 内部尝试调用 `run_command` 或 `view_file`，**父 Agent 注册的安全策略依然会对其进行审查**。
   - *例如*：如果父配置中有一条安全策略 `policy.deny("run_command")`，那么无论主 Agent 还是其派生出的任何子 Agent 尝试执行 shell 命令，都将被一致拦截并阻断，确保了多 Agent 协同下的整体安全性。

## ⌨️ 交互式命令行循环 (`run_interactive_loop`)

SDK 提供了一个快速进入多回合人机交互界面的调试工具：`run_interactive_loop(agent)`。

### 示例

```python
from google.antigravity import Agent, LocalAgentConfig
from google.antigravity.utils.interactive import run_interactive_loop

async def main() -> None:
    config = LocalAgentConfig()
    async with Agent(config) as my_agent:
        # 这一行会开启一个阻塞式的终端对话框
        # 用户可以直接在控制台与 Agent 打字聊天，退出时输入 exit 或 quit 即可
        await run_interactive_loop(my_agent)
```

这对于开发调试、测试自定义 Python 工具以及本地验证安全策略表现非常实用。
